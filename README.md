# QA 모바일 자동 증적 캡처

안드로이드 수동 QA 중 **보고하기 좋은 화면만** 자동으로 남기는 증적 수집 앱입니다.
화면에 들어가거나 누른 뒤 **화면이 다 뜨고 멈추면 1장**, 스크롤한 부분은 **한 화면에 한 장으로 이어붙여** 저장합니다.
깜빡이는 순간이나 작은 상태 변화는 하나하나 찍지 않습니다. 테스터는 평소처럼 앱을 쓰고 스크롤만 하면 됩니다.
증적은 이 기기 안에만 저장되고, 앱에 네트워크 권한이 없어 외부로 전송되지 않습니다.

- 기준 기기: Galaxy S21 / Android 15 (One UI 7) / 1080x2400 (Android 11 이상에서 동작)
- 사용자가 켜야 하는 권한: **접근성 서비스 1개** (네트워크 권한 없음)
- 설계 문서: [DESIGN.md](DESIGN.md)

**APK 고정 다운로드 주소**

```
https://github.com/YunseobSongQA/QA-Mobile-Auto-Capture/releases/download/latest/qa-capture.apk
```

## 1. 설치와 초기 설정 (Galaxy S21 / Android 15 기준)

> One UI 버전에 따라 메뉴 이름이 조금 다를 수 있습니다.

### 1-1. 크롬으로 Release에서 APK 받기

1. 휴대폰 **Chrome**에서 아래 주소를 엽니다.
   `https://github.com/YunseobSongQA/QA-Mobile-Auto-Capture/releases/tag/latest`
   (위의 고정 다운로드 주소를 열면 바로 받아집니다.)
2. **Assets**를 펼치고 `qa-capture.apk`를 누릅니다.
3. "이 유형의 파일은 기기에 해를 끼칠 수 있습니다"라는 경고가 뜨면 **다운로드**를 누릅니다.
4. 다운로드가 끝나면 화면 아래 알림에서 **열기**를 누릅니다.
   알림을 놓쳤다면 **내 파일 → 다운로드**에서 `qa-capture.apk`를 누릅니다.

### 1-2. 출처를 알 수 없는 앱 설치 허용

처음 설치하면 "보안을 위해 이 출처의 알 수 없는 앱을 설치할 수 없습니다"라는 안내가 뜹니다.

1. 안내 창에서 **설정**을 누릅니다.
2. **이 출처 허용**을 켜고 뒤로 갑니다.
3. **설치**를 누릅니다.

미리 켜 두려면 **설정 → 애플리케이션 → 오른쪽 위 ⋮ → 특별한 접근 → 출처를 알 수 없는 앱 설치 → Chrome → 이 출처 허용**으로 들어갑니다.

> **자동 차단 기능**이 켜져 있으면 스토어 밖의 앱 설치가 막힙니다.
> **설정 → 보안 및 개인정보 보호 → 자동 차단 기능**에서 끈 뒤 설치하고, 필요하면 다시 켭니다.

### 1-3. Play 프로텍트 경고 처리

사내에서 직접 서명한 앱이라 Google Play 프로텍트가 경고할 수 있습니다. 새 버전을 설치할 때마다 다시 뜰 수 있습니다.

- **앱 스캔을 권장하는 창**이 뜨면 **앱 스캔**을 누르거나 **스캔하지 않고 설치**를 누릅니다.
- **"안전하지 않은 앱 차단됨" 또는 "Play 프로텍트에서 차단됨"**이 뜨면 **세부정보 더보기 → 무시하고 설치(그래도 설치)**를 누릅니다.

Play 프로텍트를 아예 끄는 방법은 권장하지 않습니다.

### 1-4. 제한된 설정 허용과 접근성 서비스 켜기

Android 13 이상에서는 브라우저로 받은 앱이 접근성 서비스를 바로 켤 수 없고 **"제한된 설정으로 제어됨"** 안내가 뜹니다.
**앱을 업데이트(덮어쓰기 설치)할 때마다 다시 걸릴 수 있습니다.** 그때마다 아래 순서를 처음부터 다시 합니다.
앱 메인 화면의 **설정 안내** 카드에 같은 순서와 바로 가는 버튼이 있고, 서비스가 꺼져 있으면 카드가 펼쳐져 있습니다.

1. **제한된 설정 허용 (가장 먼저)**
   - 홈 화면(또는 앱스 화면)에서 **QA 증적 캡처 아이콘을 길게 누르고 ⓘ(앱 정보)**를 누릅니다.
     또는 **설정 → 애플리케이션 → QA 증적 캡처**로 들어갑니다. 앱의 **[앱 정보 열기]** 버튼도 같은 화면입니다.
   - 오른쪽 위 **⋮(점 세 개)** → **제한된 설정 허용** → PIN(또는 지문)을 입력합니다.
   - ⋮ 에 **제한된 설정 허용**이 없으면: **설정 → 접근성 → 설치된 앱 → QA 증적 캡처**를 한 번 눌러 "제한된 설정" 안내를 띄우고
     **확인**을 누른 뒤 다시 앱 정보의 ⋮ 메뉴로 갑니다(앱의 **[메뉴가 없을 때: 접근성 설정 열기]** 버튼).
2. **접근성 서비스 켜기**: **설정 → 접근성 → 설치된 앱 → QA 증적 캡처** → 스위치를 켜고, 기기 전체 제어 권한을 묻는 창에서 **허용**을 누릅니다.
   화면 오른쪽에 남색 **[● 시작]** 버튼이 뜨고 메인 화면 상태 카드가 **동작 중**(초록)으로 바뀌면 정상입니다.
   서비스가 켜지면 설정 안내 카드의 1·2단계가 자동으로 체크됩니다.
3. **배터리 "제한 없음", "사용하지 않는 앱 관리" 끄기** (다음 절 1-6). 끝나면 3단계도 체크되고 카드가 접힙니다.

### 1-5. 접근성 바로가기 (선택)

볼륨키나 접근성 버튼으로 서비스를 켜고 끕니다.

1. **설정 → 접근성 → 설치된 앱 → QA 증적 캡처**에서 **QA 증적 캡처 바로가기**를 켭니다.
2. 바로가기 방식을 고릅니다.
   - **음량 위/아래 버튼 길게 누르기**: 두 버튼을 동시에 약 3초 누르면 서비스가 켜지거나 꺼집니다. 처음 한 번은 확인 창이 뜹니다.
   - **접근성 버튼**: 화면의 접근성 버튼을 누르면 서비스가 켜지거나 꺼집니다.

바로가기로 서비스를 끄면 진행 중이던 기록이 저장되고 세션이 끝납니다.
서비스는 켜 둔 채 캡처만 잠시 멈추려면 바로가기 대신 **마스터 스위치**(2-2)를 쓰세요.

### 1-6. 배터리 "제한 없음" 설정

배터리 최적화가 서비스를 강제로 끄지 않게 합니다.

1. **설정 → 애플리케이션 → QA 증적 캡처 → 배터리 → 제한 없음**을 고릅니다.
2. 같은 앱 정보 화면으로 돌아와 **사용하지 않는 앱 관리**를 끕니다(오래 안 쓰면 권한을 회수하거나 앱을 멈추는 기능).
3. **설정 → 배터리 → 백그라운드 사용 제한**에 들어가, **절전 상태 앱**과 **초절전 상태 앱** 목록에 QA 증적 캡처가 없는지 확인합니다.

## 2. 사용법

### 2-1. 기록하기

1. 테스트할 앱을 엽니다.
2. 플로팅 버튼 **[● 시작]**(남색)을 누릅니다. 버튼이 초록 **[■ 0]**으로 바뀌면 기록 중입니다. 숫자는 확보한 이미지 수입니다.
3. 평소처럼 앱을 사용하고 스크롤합니다. **중요한 때만, 화면이 완성된 상태로** 찍습니다.
   - **찍는 때**: 화면에 들어갔을 때, 버튼·항목을 누르거나 글자를 입력한 뒤, 스크롤을 멈췄을 때.
     자동으로 넘어가는 배너나 시계처럼 앱이 혼자 바뀌는 것은 찍지 않습니다(화면 대부분이 바뀐 경우만 새 화면으로 찍음).
   - **완성된 화면**: 화면 변화가 1초 동안 없고, 0.5초 간격으로 본 두 화면이 같을 때 찍습니다.
     로딩 표시가 돌고 있으면 다 뜰 때까지 기다립니다(계속 움직이는 화면은 8초 뒤 그 시점 화면).
   - **누른 뒤 화면이 그대로면 찍지 않습니다.**
   - **작은 변화**(체크박스, 글자 입력 등)는 새 이미지를 만들지 않고 그 화면 이미지를 최신 상태로 바꿉니다.
     **뚜렷한 변화**(오류 문구, 펼친 내용 등)는 같은 화면의 다음 이미지(`_2`, `_3`)로 저장합니다.
   - 플로팅 버튼은 저장할 1장을 찍는 순간에만 잠깐 사라집니다. 그래서 결과 이미지에 버튼이 찍히지 않습니다.
4. **스크롤하는 동안은 찍지 않습니다.** 멈출 때마다(0.4초 정도 가만히 있으면) 화면을 모았다가, 다른 화면으로 넘어가면
   그 화면의 맨 위부터 스크롤한 부분까지 **한 장으로 이어붙여** 저장합니다.
   - 상단 헤더와 하단 탭바는 이미지의 맨 위와 맨 아래에 한 번씩만 나옵니다.
   - **한 번에 화면 높이보다 적게** 스크롤하고 잠깐 멈추는 식으로 넘기면 겹치는 부분으로 정확히 이어집니다.
     너무 많이 넘겨 겹침이 없으면 억지로 붙이지 않고 다음 번호(`_2`)로 나눠 저장합니다. 20,000px를 넘어도 나눕니다.
5. 버튼을 다시 누르면 정지합니다. "QA 기록 저장 완료" 메시지가 뜹니다.
6. 버튼을 **길게 누르면** 앱 메인 화면이 열립니다.

- 화면 이미지는 **그 화면을 떠날 때** 저장됩니다(그 전까지는 임시 파일).
- 1초도 머물지 않고 지나간 화면은 저장하지 않습니다.
- 버튼은 끌어서 옮길 수 있습니다.
- 홈 화면, 알림창, 키보드, 이 앱 자신은 기록하지 않습니다. 홈으로 나가면 기다리던 촬영을 버립니다.
- 토스트 문구는 시각과 함께 세션 로그(`session_log.txt`)와 `manifest.json`의 `toasts`에 기록됩니다.

### 2-2. 캡처 일시정지/재개 (마스터 스위치)

접근성 서비스는 켜 둔 채 캡처만 멈출 수 있습니다. 개인 메신저 확인처럼 기록하면 안 되는 화면을 볼 때 씁니다.

- **앱 메인 화면 맨 위 상태 카드의 스위치**, 또는 **알림창 빠른 설정의 "QA 캡처" 타일**을 누릅니다.
- 일시정지하면 플로팅 버튼이 사라지고 화면 감지와 캡처를 모두 멈춥니다. 기록 중이었다면 그 세션을 저장하고 끝냅니다.
- 다시 켜면 플로팅 버튼이 나타납니다. 기록은 버튼으로 새로 시작합니다.
- 상태는 재부팅, 앱 재시작, 덮어쓰기 설치 뒤에도 그대로입니다.

**빠른 설정 타일 추가(최초 1회)**: 화면 위에서 두 번 쓸어내려 빠른 설정을 펼칩니다 → **⋮(또는 연필) → 편집** →
**사용 가능한 버튼**에서 **QA 캡처**를 길게 눌러 위쪽 목록으로 끌어 놓고 **완료**를 누릅니다.
타일 아래 글자는 **동작 중 / 기록 중 / 일시정지 / 서비스 꺼짐**을 보여 줍니다.

### 2-3. 앱 화면

- **상태 카드**: 동작 중(초록), 일시정지(회색), 서비스 꺼짐(빨강)과 마스터 스위치
- **설정 안내**: 1-4절의 3단계와 바로 가는 버튼. "앱을 업데이트하면 이 과정을 다시 해야 합니다" 안내가 맨 위에 있습니다.
  끝난 단계는 체크 표시되고, 서비스가 꺼져 있으면 펼쳐진 상태, 모두 끝나면 접힌 상태입니다(제목을 눌러 펼치고 접기).
- **저장된 세션**: 날짜, 이미지 수, [열기]. 열면 이미지 목록(누르면 크게 보기), **[zip으로 공유]**, **[세션 로그]**가 있습니다.
- **개인정보 및 권한**: 접근성으로 읽는 정보, 저장 위치, 외부 전송 없음(네트워크 권한 없음)
- **설정**(오른쪽 위 톱니바퀴): 안정화 대기 `SETTLE_MS`(0.5~3초, 기본 1초), 최대 대기 `MAX_WAIT_MS`(3~30초, 기본 8초), 디버그 로그.
  타이밍은 바로 적용됩니다. 디버그 로그는 기록 중 받은 모든 접근성 이벤트와 캡처 판단(`#SHOT` 촬영, `#FRAME` 확보, `#NOCHANGE` 안 찍음, `#SCROLL` 스크롤 시작·멈춤)을
  `Documents/QAEvidence/debug/{세션}.txt`로 저장하며, 다음 기록 시작부터 적용되고 배터리를 더 씁니다.
- 다크 모드를 따릅니다.

### 2-4. 결과물

```
내장 저장공간/Documents/QAEvidence/
├── 20261015_103000/                                  ← 세션 시작 시각
│   ├── 001_settings_Settings_103000.png               ← 설정 첫 화면(스크롤한 부분까지 한 장)
│   ├── 002_settings_SubSettings_103045.png            ← 다음 화면
│   ├── 002_settings_SubSettings_103045_2.png          ← 같은 화면에서 뚜렷이 바뀐 상태(오류 문구 등)
│   ├── 003_settings_Settings_103120.png               ← 첫 화면으로 돌아옴(새 순번)
│   ├── manifest.json
│   └── session_log.txt                                ← 화면 진입, 저장 파일, 토스트 문구를 시각과 함께
├── 20261015_103000.zip                               ← [zip으로 공유]를 누르면 생성 (디버그 로그가 있으면 debug_log.txt 포함)
└── debug/
    └── 20261015_103000.txt                           ← "디버그 로그" 설정
```

- 파일 이름: `{화면 순번}_{앱 패키지 끝부분}_{화면 클래스 짧은 이름}_{화면 진입 시각 HHmmss}[_상태 번호].png`.
  이름순으로 정렬하면 시간순입니다. 같은 화면을 다시 방문하면 새 화면 순번이 붙습니다(A→B→A = 순번 3개).
- `manifest.json`: 화면별 순번, packageName, className, 진입/이탈 시각, 이미지 목록(파일명, 시각, 이어붙인 화면 수 `frames`), 토스트 기록(`toasts`).
- 사양에는 `Pictures/`로 되어 있었지만, 저장소 권한 없이는 `Pictures/`에 manifest.json을 만들 수 없어서 `Documents/`에 저장합니다([DESIGN.md](DESIGN.md) 0-1). PNG는 갤러리 앱에서도 보입니다.

### 업데이트

`main`에 push하면 새 APK가 같은 주소에 올라갑니다. 받아서 **덮어 설치**하면 됩니다. 마스터 스위치 상태와 세션 목록은 그대로 유지됩니다.
설치 후 접근성 서비스가 꺼지고 "제한된 설정으로 제어됨"이 다시 뜨면 1-4절(앱의 설정 안내 카드) 순서대로 **앱 정보 ⋮ → 제한된 설정 허용**부터 다시 합니다.
항상 같은 서명 키로 빌드하므로 앱을 삭제할 필요는 없습니다.

### 실기기 확인 체크리스트

- [ ] 화면에 들어가 가만히 있으면 그 화면 이미지 1장만 생기고, 더 늘지 않는다.
- [ ] 로딩이 있는 화면은 로딩 표시가 아니라 다 뜬 화면이 저장된다.
- [ ] 스크롤하는 동안 이미지가 늘지 않고, 긴 목록을 조금씩 끝까지 내린 뒤 다른 화면으로 가면 맨 위부터 끝까지 한 장이 생긴다(헤더·탭바 한 번씩, 중복·잘림 없음).
- [ ] 체크박스·글자 입력 같은 작은 변화는 새 이미지 없이 최신 상태로 바뀌고, 오류 문구처럼 뚜렷한 변화는 `_2`로 생긴다.
- [ ] 자동으로 넘어가는 배너가 있는 화면에 가만히 있어도 이미지가 늘지 않는다.
- [ ] 토스트 문구가 `session_log.txt`에 시각과 함께 남는다.
- [ ] 플로팅 버튼은 이미지 1장을 확보할 때만 잠깐 사라지고, 결과 이미지에 찍히지 않는다.
- [ ] 화면 A→B→A로 이동하면 화면 순번 001, 002, 003 이 순서대로 생긴다.
- [ ] 업데이트 후 서비스가 꺼졌을 때 설정 안내 카드가 펼쳐지고, 앱 정보 ⋮ → 제한된 설정 허용부터 순서대로 하면 1~3단계가 체크되며 카드가 접힌다.
- [ ] 빠른 설정 타일·메인 스위치로 일시정지하면 버튼이 사라지고 캡처가 멈추며, 재부팅 후에도 상태가 유지된다.
- [ ] 30분 연속 사용해도 앱이 죽지 않는다.

## 3. 개발

### 로컬 빌드 (GitHub Codespaces)

Android Studio 없이 Gradle CLI로 빌드합니다. JDK 17 이상이 필요하고, CI는 JDK 21을 씁니다.
Android SDK(platform 35, build-tools 35)의 위치는 `local.properties`의 `sdk.dir` 또는 `ANDROID_HOME`으로 지정합니다.

```bash
./gradlew testDebugUnitTest   # 정지 확인·스크롤 멈춤·이어붙이기 단위테스트 (JVM)
./gradlew assembleRelease     # 서명 환경변수가 없으면 app-release-unsigned.apk
```

로컬에서 서명된 APK를 만들려면 환경변수 `KEYSTORE_PATH`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`를 지정합니다.

### 서명 키 준비 (최초 1회)

항상 같은 키로 서명해야 덮어쓰기 설치와 접근성 권한 유지가 됩니다. **키스토어 파일은 절대 커밋하지 않습니다.**
`.gitignore`에 `*.jks`, `*.keystore`가 들어 있지만, 실수를 막기 위해 저장소 밖(홈 폴더)에서 만듭니다.

**1) 키스토어 생성** (Codespaces 터미널)

```bash
cd ~
keytool -genkeypair -v \
  -keystore qa-capture-release.jks -storetype PKCS12 \
  -alias qa-capture -keyalg RSA -keysize 4096 -validity 10000 \
  -dname "CN=QA Auto Capture"
```

비밀번호를 두 번 입력합니다. PKCS12 형식에서는 **키 비밀번호가 키스토어 비밀번호와 같습니다.**

**2) base64로 변환**

```bash
base64 -w 0 ~/qa-capture-release.jks > ~/qa-capture-release.jks.b64
```

**3) GitHub Secrets 등록**

저장소 페이지 → **Settings → Secrets and variables → Actions → New repository secret**에서 4개를 등록합니다.

| 이름 | 값 |
|---|---|
| `KEYSTORE_BASE64` | `qa-capture-release.jks.b64` 파일 내용 전체 (`cat ~/qa-capture-release.jks.b64`) |
| `KEYSTORE_PASSWORD` | 1)에서 정한 비밀번호 |
| `KEY_ALIAS` | `qa-capture` |
| `KEY_PASSWORD` | 1)에서 정한 비밀번호 (키스토어 비밀번호와 동일) |

`gh` CLI에 저장소 Secrets 권한이 있으면 터미널에서도 등록할 수 있습니다.

```bash
gh secret set KEYSTORE_BASE64 < ~/qa-capture-release.jks.b64
gh secret set KEYSTORE_PASSWORD   # 입력 프롬프트에 비밀번호 붙여넣기
gh secret set KEY_ALIAS --body qa-capture
gh secret set KEY_PASSWORD
```

**4) 백업 후 삭제**

Codespace를 삭제하면 파일도 사라집니다. `qa-capture-release.jks`(VS Code 탐색기에서 우클릭 → 다운로드)와 비밀번호를 안전한 곳(비밀번호 관리자 등)에 보관하세요. 그다음 Codespace에서는 지웁니다.

```bash
rm ~/qa-capture-release.jks ~/qa-capture-release.jks.b64
```

> 키를 잃어버리면 새 키로 서명한 APK는 덮어 설치할 수 없습니다. 앱을 삭제하고 다시 설치해야 하고, 접근성 권한과 제한된 설정 허용을 다시 해야 합니다. 이전 세션도 목록과 공유에서 빠집니다(파일은 남습니다).

### 배포 (GitHub Actions)

`.github/workflows/release.yml`은 `main`에 push하거나 Actions 탭에서 수동 실행하면 아래 순서로 동작합니다.

1. 서명 Secrets 4개 확인. 하나라도 없으면 실패하고 이 절을 안내합니다.
2. 단위테스트 `./gradlew testDebugUnitTest`
3. 키스토어 복원 → `./gradlew assembleRelease` → `qa-capture.apk`로 이름 변경
4. APK에 네트워크 권한이 없는지 확인. 있으면 배포하지 않습니다.
5. `latest` 태그를 현재 커밋으로 옮기고, GitHub Release `latest`(prerelease)에 `qa-capture.apk`를 덮어쓰기로 업로드

versionCode는 GitHub run number로 자동 증가합니다. versionName은 `1.0.{run number}`입니다.

## 4. 권한과 개인정보

- 사용자가 켜는 권한은 **접근성 서비스 1개**뿐입니다.
- **네트워크 권한이 없습니다.** 앱이 인터넷에 연결할 수 없어 증적이 외부로 전송되지 않습니다. Manifest에서 INTERNET 권한을 명시적으로 제거했고, 배포 전 CI가 APK에 네트워크 권한이 없는지 확인합니다. 기기 밖으로 나가는 경우는 사용자가 [zip으로 공유]를 누를 때뿐입니다.
- 접근성으로 읽는 것: 화면 전환·스크롤·내용 변경 알림(앱 이름, 화면 이름), 토스트 문구, 기록 중일 때의 화면 캡처. 화면의 글자 내용은 디버그 로그를 켠 경우에만 기록합니다.
- 저장 위치: 이 기기의 `내장 저장공간/Documents/QAEvidence`. 기록 중일 때만 저장합니다.
- 포그라운드 서비스, 알림, 다른 앱 위에 표시(오버레이), 저장소 권한을 쓰지 않습니다.

## 5. 알려진 한계

- `FLAG_SECURE` 화면(은행 앱 등), 동영상과 애니메이션이 많은 화면은 지원 범위 밖입니다.
- 완성 확인에 약 1.5초가 걸리므로 그보다 빨리 지나간 화면·상태는 남지 않습니다.
- 작은 변화는 마지막 상태만 남습니다(중간 상태는 안 남음).
- 누를 때 터치 알림을 보내지 않는 앱 화면(일부 Compose 화면)은 누른 뒤 일부만 바뀐 결과가 바로 찍히지 않고, 다음 터치·스크롤 때 함께 찍힙니다.
- 아주 작은 로딩 표시는 정지로 보고 찍을 수 있습니다. 토스트가 떠 있는 동안 화면이 멈추면 토스트가 찍힌 화면이 저장됩니다.
- 스크롤은 멈출 때만 찍으므로 빠르게 튕겨 화면 높이보다 많이 넘어가면 그 사이 내용이 빠지고 `_2`로 나뉩니다. 화면에 들어오자마자(0.4초 안) 스크롤하면 첫 멈춤 위치부터 이어집니다.
- 한 Activity 안에서 화면이 바뀌는 앱(Fragment, Compose 내비게이션)은 화면 순번이 늘지 않고 `_2`, `_3`으로 저장됩니다.
- 나머지는 [DESIGN.md](DESIGN.md) 10장을 참고하세요.
